同数据训练的语言模型仍会因预训练种子而呈现不同越狱脆弱性

论文针对同一份预训练数据下，不同预训练运行是否会沿用相同的越狱失效模式开展实验。实验覆盖25种预训练数据配方，每种配方包含3个预训练种子、每个种子1B参数基础模型及2个安全后训练种子，共计150个模型；每个模型均对一组共享越狱提示收集20次回答。结果显示，同一预训练运行的两个后训练副本在各提示上的拒答率平均相关系数为0.984，更换预训练种子后降至0.811，更换数据配方后为0.779，该规律在25种配方以及150M和300M参数规模下均成立。

Insight by AI 模型安全评测若只测试单一检查点，容易把偶然的预训练运行特征误判为数据配方或安全训练造成的稳定属性；越狱基准需要纳入多预训练种子重复测量。

parse_number() SQLite 扩展实测：新 C 实现每行耗时最低，Rust 产物文件更大

Simon Willison 比较了用 C 与 Rust 构建 SQLite parse_number() 扩展的性能、代码复杂度和产物大小，该函数可处理带千位分隔符、货币符号、百分号及负号的字符串。首轮原型中，Rust 扩展使用 Rusqlite 和 sqlite-loadable-rs 时的文件大小分别为 321 KB 和 298 KB，C 扩展为 14 KB，而 Rust 版本运行更快。后续优化的新 C 实现在 200 万行测试中取得最低的每行净耗时：混合数据为 19 ns、纯整数为 16 ns、纯小数为 18 ns，对应 Rusqlite 分别为 46 ns、36 ns 和 55 ns，sqlite-loadable-rs 分别为 41 ns、32 ns 和 47 ns。研究还记录了使用 Claude 生成和改写 C 版本及研究报告的过程。

Insight by AI 这一案例说明，Rust 并非 SQLite 扩展在运行速度和产物体积两个维度上的绝对优势；借助模型辅助迭代，C 实现也展示出更低的运行开销，但结论目前限于作者测试的函数、输入类型和两百万行样本。
